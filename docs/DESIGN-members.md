# 설계안: 작업실 멤버 입장과 함께 쓰는 기록

작성 2026-11-14 · 상태: **검토 중(구현 전)** · 대상: Y-Place 개인 작업실 1~4

이 문서는 "입장 코드로 들어오는 멤버, 자기 방, 서버에 남는 기록, 서로 보이는 진행 상황"을 어떻게 만들지 정리한 설계안입니다. 승인 전에는 코드를 바꾸지 않습니다. 마지막의 "결정할 것"에 답해 주시면 그대로 구현합니다.

---

## 1. 무엇이 달라지나

| 지금 | 바뀐 뒤 |
|---|---|
| 누구나 공개 주소로 들어와 작업실 1~4 중 아무 방이나 고른다 | 라운지·모임방은 지금처럼 누구나. **개인 작업실 문은 멤버만** 연다 |
| 기록은 그 브라우저에만 남는다 | 기록이 서버에 남아 **다른 기기에서도 이어진다** |
| 문을 누르면 방을 고른다 | 멤버는 문을 누르면 **자기 방으로 바로** 들어간다 |
| 다른 사람이 뭘 하는지 모른다 | 라운지 '오늘 보드'에서 멤버별 상태·오늘 시간·목표 체크가 보인다 |

라운지는 계속 공개 공간으로 둡니다. 작업실만 멤버 전용입니다.

## 2. 프로젝트 원칙과 부딪히는 부분 (먼저 결정 필요)

Y-Place와 공통 규칙은 **로그인·채팅·개인정보 수집을 범위 밖**으로 둡니다. 이 설계는 그중 일부를 건드립니다.

| 항목 | 이 설계에서 | 원칙과의 관계 |
|---|---|---|
| 입장 코드 + 닉네임 + PIN 4자리 | 넣음 | **로그인에 해당.** 이메일·전화번호·실명은 받지 않는다 |
| 개인 기록(세션·목표·회고)을 서버에 저장 | 넣음 | **개인정보에 가까움.** 회고 메모·할 일은 본인만 읽게 한다 |
| 1:1 쪽지(쉬는 시간에 전달) | 선택 | **채팅에 해당.** 한 줄 쪽지만, 실시간 대화창은 없음 |
| 전체 대화 | 넣지 않음 | 채팅 |
| 카메라·마이크·화면 공유, 탭 이동 추적 | 넣지 않음 | 금지 유지 |

→ 승인하시면 Y-Place `AGENTS.md`와 공통 규칙 문서에 "작업실 멤버 기능에 한해 허용"으로 범위를 고쳐 적습니다.

## 3. 입장 흐름

```
라운지 "개인 작업실" 문 클릭
 ├─ 이 기기가 이미 멤버로 연결됨 → 자기 방(work1~4)으로 바로 입장
 └─ 처음 / 다른 기기
     ├─ [처음 입장]  입장 코드 + 닉네임 + PIN 4자리 → 빈 방 하나 배정 → 입장
     └─ [이어서 입장] 닉네임 + PIN → 이 기기를 내 기록에 연결 → 입장
```

- **방 배정:** 처음 입장할 때 비어 있는 작업실 번호를 차례로 준다. 운영자가 나중에 바꿀 수 있다.
- **정원:** 작업실 수와 같은 4명. 다 차면 "지금은 자리가 없어요"라고 띄우고 새 입장을 막는다.
- **운영자 기능:** 입장 코드 바꾸기, 멤버 내보내기(방이 비고 기록은 보관), 방 번호 바꾸기, PIN 초기화.
- **내 방이 아닌 작업실:** 멤버도 남의 방에는 들어가지 않는다. 대신 라운지 오늘 보드에서 상태를 본다.

`app.ts`의 `resolveWorkRoom()`이 "이 기기의 멤버 → 방 번호"를 돌려주게 바꾸면, 지금 만든 문 하나 구조 그대로 분기됩니다.

## 4. 기술 구성

- **Supabase 프로젝트를 새로 만든다(Y-Place 전용).** 비북스-M 프로젝트와 섞지 않는다(공통 규칙 3장).
- **익명 로그인(Anonymous Sign-in):** 기기마다 보이지 않는 세션이 생긴다. 이메일 없이 서버가 "이 기기"를 구분하는 용도다.
- **입장 코드와 PIN은 서버에서만 확인한다.** 브라우저 코드에는 코드값이 없다. 저장은 해시(`pgcrypto`의 `crypt`)로만 한다.
- **확인은 서버 함수(RPC) 3개로만 한다.** 테이블을 직접 읽어 코드를 맞춰 보는 길이 없다.
  - `join_room(code, nickname, pin)`: 처음 입장(코드 확인 → 멤버 생성 → 방 배정 → 이 기기 연결)
  - `resume_member(nickname, pin)`: 이어서 입장(PIN 확인 → 이 기기 연결)
  - `owner_*`: 운영자 전용(코드 변경, 내보내기, 방 변경, PIN 초기화)
- **PIN 4자리는 무작위 대입에 약하다.** 그래서 닉네임별로 5번 틀리면 15분 잠그고, 입장 코드도 기기별로 시도 횟수를 제한한다.
- **실시간 상태(집중/휴식/자리 비움/퇴근, 타이머 진행):** 기존 Realtime presence를 쓴다. 상태가 바뀔 때만 보낸다(위치 스트림 없음, 비북스-M에서 줄인 방식 그대로).
- **데모 모드 `?demo=1`:** 서버 없이 가짜 멤버 3명과 로컬 저장으로 화면을 확인한다.

## 5. 데이터 구조

| 테이블 | 주요 칸 | 누가 읽나 | 누가 쓰나 |
|---|---|---|---|
| `rooms` | 이름, 입장 코드 해시, 정원 | 멤버(코드 해시 제외) | 운영자 RPC |
| `members` | 닉네임, PIN 해시, 방 번호, 역할(owner/member), 내보낸 날 | 같은 방 멤버(PIN 해시 제외) | RPC만 |
| `member_devices` | 익명 사용자 id → 멤버 | 본인 | RPC만 |
| `sessions` | 시작·끝, 집중 시간, 결과(했다/일부/못 했다) | 같은 방 멤버 | 본인 |
| `session_notes` | 할 일, 집중도, 회고 메모 | **본인만** | 본인 |
| `day_goals` | 날짜, 목표 목록, 체크, 공개 여부 | 공개면 멤버, 아니면 본인 | 본인 |
| `parking` | 딴생각 한 줄 | **본인만** | 본인 |
| `cheers` | 보낸 사람, 받는 사람, 종류(커피·박수·쪽지), 짧은 글, 만든 시각 | 보낸 사람·받는 사람 | 멤버 |
| `challenges` | 개인/공동, 목표 시간, 기한, 참여자 | 같은 방 멤버 | 멤버(공동은 운영자) |

- **권한(RLS):** 모든 테이블에 켠다. `current_member()` 함수가 "이 기기의 멤버"를 돌려주고, 정책은 "같은 방이면 읽기, 본인 것만 쓰기"를 기본으로 한다. 회고 메모·할 일·딴생각은 따로 떼어 본인만 읽는다.
- **응원:** 받은 날 하루 동안만 책상에 보인다(`created_at` 기준). 지우지 않고 기록으로 남긴다.
- **이미 쌓인 기록:** 처음 입장할 때 "이 브라우저에 있던 기록 n개를 올릴까요?"를 묻고, 동의하면 올린다.

## 6. 화면에 생기는 것

- **입장 창:** 처음 입장(코드·닉네임·PIN) / 이어서 입장(닉네임·PIN) 두 탭.
- **라운지 '오늘 보드'**(칠판 모양 소품, 누르면 열림): 멤버별 상태 색, 오늘 누적 시간, 목표 체크, 들어온 시각·나간 시각.
- **작업실 문 간판 옆 작은 불빛 4개:** 방마다 집중(남색)·휴식(초록)·비어 있음(꺼짐). 라운지에서 한눈에 보인다.
- **함께 시작:** 정각·30분에 "다 같이 50분" 안내. 누르면 내 타이머가 같은 시각에 맞춰 시작된다.
- **응원:** 오늘 보드에서 멤버 옆 커피·박수·쪽지 버튼. 받은 사람 책상에 머그·포스트잇이 생긴다. 상대가 집중 중이면 쉬는 시간에 보여 준다.
- **공동 챌린지:** 오늘 보드 아래 진행 바. 예) "이번 달 다 함께 120시간". 달성하면 라운지 조명 연출과 축하 쪽지.
- **함께 자라는 공간:** 방 전체 누적 시간에 따라 라운지 화분이 커지고, 서가에 책이 한 권씩 늘어난다.

## 7. 무료 플랜 안에서 버티는지

| 항목 | 예상 사용량(멤버 4명, 하루 8시간) | Supabase 무료 한도 |
|---|---|---|
| DB 용량 | 세션 1건 약 300바이트 → 1년 수 MB | 500MB |
| Realtime 메시지 | 상태 변경만(1인당 하루 수십 건) → 월 수만 건 | 월 200만 건 |
| 동시 연결 | 라운지 방문객 포함 수십 | 200 |
| 일시정지 | 무료 프로젝트는 오래 쓰지 않으면 멈출 수 있음 | 대시보드에서 다시 켜기 |

- 한도 수치는 2026-11-12에 공식 문서로 확인했습니다. 일시정지 기준(비활성 기간)은 도입 전에 다시 확인합니다.
- 서버가 멈추거나 한도를 넘어도 라운지·모임방은 그대로 열리고, 작업실은 "오프라인 기록"(지금 방식)으로 내려가게 만듭니다.

## 9. 결정할 것

1. **범위:** 작업실 멤버 기능에 한해 로그인(입장 코드+닉네임+PIN)과 개인 기록 서버 저장을 허용할까요?
2. **쪽지:** 쉬는 시간에 전달되는 한 줄 쪽지(1:1)를 넣을까요, 커피·박수만 둘까요? (전체 대화는 넣지 않는 안)
3. **정원:** 멤버 4명(작업실 수와 같게)으로 할까요? 운영자 본인도 작업실 하나를 쓰나요?
4. **공개 범위:** 오늘 보드의 "오늘 목표"를 기본 공개로 할까요, 기본 비공개로 할까요?
5. **라운지:** 지금처럼 누구나 들어오는 공개 라운지로 둘까요, 라운지도 멤버 전용으로 닫을까요?
